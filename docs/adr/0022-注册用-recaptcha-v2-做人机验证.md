# 注册用 reCAPTCHA v2 做人机验证

ADR-0018 开放了自助注册，并明确接受了两条风险：不做限流，不设邀请码名额上限。代价是邀请码一旦泄露，除了让超级管理员拉全站总闸，没有任何自动止损手段。在注册这一步加人机验证，把那半条风险补上。

用 Google reCAPTCHA v2 的复选框版。选 v2 而不是 v3：v3 是无感打分，站点自己定阈值，用户全程什么都不做；产品要的是「用户必须手动验证」，那就是那个「我不是机器人」的复选框。

## 先试过并放弃的：ALTCHA

先接过 ALTCHA（MIT，工作量证明，自托管、无第三方），因为它不需要额外容器、不把访客交给外部服务。接完实测发现难度标定不成立：

同一道题在 Node 里解只要 0.6 秒，在浏览器里要 **54 秒**。原因是 PBKDF2 在浏览器 WebCrypto 里每次 `deriveBits` 的调用开销比 Node 原生高两个数量级，而工作量证明恰恰要串行做上千次派生。我最初在 Node 上标定难度，量错了平台。

把难度降到浏览器能接受的水平，工作量证明也就不剩什么门槛了。这条路在这个算法下走不通，整个撤掉。

## Consequences

- **注册依赖 Google**。访客的浏览器要能加载 `google.com/recaptcha`，服务端要能出网打 `siteverify`。这是接受第三方换来的强度：reCAPTCHA 靠行为分析，比工作量证明扛得住有针对性的攻击者。部署在访问不了 Google 的地区会直接失效。
- 两把密钥存在全站设置表而不是环境变量：换密钥不必重新部署，开注册的人和去 Google 后台申请密钥的是同一个人，在同一个页面填完最顺。私钥只进不出，任何接口都不回传它，设置接口只回一个「配没配」。
- **失败一律往安全的一边倒**。密钥没配齐时注册当关着；校验器抛异常（Google 不可达、网络抖动）时按未通过处理并记一条 warn，而不是让它变成 500。宁可把人挡在门外，也不能因为一次网络抖动就把匿名入口敞开。
- 校验做成可注入的依赖，与 `geo` 同一个套路：测试注一个假的，不真打 Google。
- 验证排在注册流程最前面，在账号冲突检查和 argon2 哈希之前——后面每一步都比它贵，而且提前挡住也不会泄露账号占没占。
- 令牌两分钟过期且只能用一次，Google 侧保证，本地不需要防重放的表。注册失败后前端会重置控件，因为同一枚令牌过不了第二回。
- **Google 的公开测试密钥对任何令牌都返回通过**，`hostname` 字段会是 `testkey.google.com`。它是给本地联调用的，留在生产配置里等于人机验证形同虚设。后台识别到它会显眼地报警，服务端每次注册也记一条 warn。之所以不直接拒绝，是因为拿它本地联调是正当用法。**用这对密钥做的验证不能当作「人机验证生效」的证据**——它证明的只是调用链通了。
