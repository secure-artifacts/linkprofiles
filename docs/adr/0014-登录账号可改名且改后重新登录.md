# 登录账号可改名，改后全部设备重新登录

账号原先只能在创建时确定，后台的「账号设置」只能改备注和密码。实际运营中批量创建、临时命名会留下难以辨认的登录账号，因此允许后续改名。

账号是登录凭证，不是个人页地址。修改账号不得触碰 `profiles.short_name`、页面内容、埋点、媒体或 API Key。

## Decision

- 新建和改名统一使用 3–32 位小写字母、数字、点、下划线或横线；全站按小写唯一。
- 历史宽松账号不批量重写，避免迁移时让现有用户失去登录能力；它们主动改名时才进入新规则。
- 用户自助改名必须验证当前密码。管理员可改名下用户，超级管理员可改任意用户与管理员。
- 改名与写 `account_name_changes` 流水在同一事务中完成。
- 改名成功后删除目标账号的全部会话。旧账号不做别名，也不能继续登录。

## Consequences

- 登录查询兼容历史账号的精确值，同时对标准账号提供不区分大小写的匹配。
- 数据库唯一索引改为 `lower(account)`；上线前必须审计现有数据是否存在仅大小写不同的重复账号。
- 后台界面必须区分「登录用户名」「后台备注」「页面地址」「页面显示名」，不再把它们笼统叫用户名。
