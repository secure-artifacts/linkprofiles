# 图片裁切放在浏览器里做，不保留原图

用户要求头像位与背景图支持上传后编辑构图（缩放、移动、看得见裁切 mask）。此前的行为是：服务端 `sharp().resize({ fit: 'inside', withoutEnlargement: true })` 等比缩放**不裁切**，公开页靠写死的 `object-fit: cover` / `background-size: cover` 居中裁 —— 用户对构图没有任何控制权，头像被裁掉半张脸也只能换一张图重传。

## Considered Options

- **服务端裁切，schema 存裁切参数**：`profiles` 加 `avatar_crop_x/y/w/h` 之类的列，原图落盘，每次改布局或换比例都能从原图重裁。最灵活，但要动数据库 schema、动 sharp 管线、动 `profile-ui` 的渲染层（三处都得知道裁切框），并且原图长期占磁盘。为一个构图功能付这么多改动，不值。
- **客户端裁切，裁好的结果顶替原文件上传（选定）**：canvas 导出裁切区域 → 走现有的 `PendingMedia` 流程（blob 预览、保存时才 POST）。**服务端与 `profile-ui` 一行不用改**，它们收到的就是一张已经按目标比例裁好的图，原来的等比缩放与 `cover` 行为恰好变成无操作。

## Consequences

- **原图不保留**，服务端只有裁切结果。事后想重裁、或换一种布局后重新适配，都要重新上传原图。裁切弹窗里对此有明示（「原图不会保留」加粗）。
- 编辑器在**本次会话内**用 state 留一份原图（`MediaEditor` 的 `sources`），所以刚上传完点「重新裁切」回到的是原图而不是已裁结果 —— 否则反复重裁会越裁越小。刷新页面这份缓存就没了，此后只能重新上传。
- 裁切框宽高比按 slot 写死：头像位 1:1，背景图 375×812（移动端竖屏）。缩放下限是「刚好铺满裁切框」，平移被夹在不露白的范围内 —— 裁出来的图一定是满的，公开页那边的 `cover` 不会再二次裁一刀。
- 导出统一走 JPEG（质量 0.92），长边上限 1600px。裁完铺满整个画布，不存在需要保留的透明区域，而 PNG 在照片上体积能大出几倍，直接顶到上传大小上限。**扩展名会变**：传进去 `a.png`，存下来是 `a.jpg`。
- 头像裁切框画的是方框 + 一个虚线圆：导出的是方形，圆是公开页用 CSS 裁的。遮罩层用超粗边框挖洞实现，超粗边框下内边界的圆角会被减到 0，挖出来必然是方角 —— 这里正好就是想要的，不是缺陷。
- **视频头像不裁切**，维持原状：服务端本就不转码，抽首帧当封面即可。
- 依赖 canvas 与 `URL.createObjectURL`，无额外三方库。
