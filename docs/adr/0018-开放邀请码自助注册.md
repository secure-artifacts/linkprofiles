# 开放邀请码自助注册

ADR-0005 开篇写的是「系统是内部自用、无公开注册的」，整套归属分权建在这句上。现在有几千人排队等开户，逐个由管理员创建不成立了。

开放自助注册：访客在后台里的注册页填账号、密码、邀请码和 short_name，一次事务同时建出账号和它的第一个个人页，注册完跳回登录页自己登一次。邀请码决定他落进哪个区域，账号立刻可用，不经人工审核——加审核等于把管理员的工作量原样搬回来，与这次改动的出发点相悖。

注册页做进 admin 这个 SPA（`/_admin/register`），与登录页共用同一套组件，不新增服务端渲染路径，因此不触及 ADR-0004 对公开页零 hydration 的约定。

邀请码默认由系统随机生成，管理员可以改成好记的字符串。全站唯一，与区域多对一：一个区域先后可以有多个码，后台任一时刻只呈现当前有效的那一个，重置即换码，已注册用户不受影响。

## Consequences

- 这是本系统第一个匿名写入口。**明确接受的风险**：不加限流，也不做邀请码名额上限。邀请码泄露后没有任何自动止损，只能靠超级管理员拉全站注册总闸。总闸放在全站设置里，与来源透传默认值并列。
- 上一条的代价具体是：泄露的码可以被无限次使用，而 short_name 一旦被占，删除后进墓碑永不再分配，这个污染不可逆。允许管理员自定义邀请码进一步扩大了猜中的可能。若后续要补救，优先级是名额上限、然后是限流。
- 登录接口同样没有限流，本次不改。
- **注册接口是一个匿名的账号存在性预言机**：账号重复、short_name 重复、撞墓碑各给一个可区分的错误码（产品要求，注册者得知道该改哪一个），于是持码者可以逐个验证任意账号名是否已被注册。账号全站唯一，这一点没法按区域分命名空间——真去分了，注册时说「可用」、入库却撞唯一索引，反而更糟。short_name 的存在性本来就是公开的（`域名/{short_name}` 要么渲染要么 404），账号的存在性是这次新暴露的。它与「登录接口不限流」叠在一起会放大定向撞库的效率，这是本决定的实际代价。
- **自定义邀请码把码的强度交给了管理员**。系统随机生成的是 10 位、32 字符表，约 1.1×10^15 种；管理员自定义可以短到 8 位（约 1.1×10^12），但真正的风险不是穷举而是他会取一个人能想出来的词。在不限流的前提下，一个好记的码等于一个弱口令。
- 注册页会向注册者显示「你将加入 XX」，因此区域名从内部标签变成对外文案，取名要按对外标准。
- short_name 在注册表单里现场校验，走既有的冲突判定（含墓碑），前端失焦实时提示。整单在一个事务里，short_name 被并发抢注则整单失败，用户重填。
- ADR-0005 的分权规则仍然有效，只是它「无公开注册」的前提作废；归属载体的变化见 ADR-0017。
