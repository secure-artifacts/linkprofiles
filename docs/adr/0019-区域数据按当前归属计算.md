# 区域数据按当前归属计算，历史不做快照

管理员可以把用户从一个区域移到另一个。那么这个用户之前产生的点击、线索和页面浏览，在区域维度上算旧区域的还是新区域的？

选择按**当前**归属计算：分析查询实时沿「用户 → 区域」这条链取归属，埋点事件与日汇总都不冗余区域字段。用户一移区，他的全部历史数据立刻整体计入新区域。

放弃的方案是在事件上快照区域，按发生时的归属统计。它能让历史报表可复现，但会破坏 ADR-0015 立的恒等式：用户移走后，他的历史事件留在旧区域，而他的个人页已在新区域，「区域总览」就不再等于「区域内全部个人页之和」。ADR-0015 明确要求上层指标等于下层之和，加新维度时先确认这个恒等式还成立——快照方案通不过这一关。

## Consequences

- 恒等式扩展为四层并保持成立：总览 = 全部可见区域之和 = 全部账号之和 = 全部个人页之和。区域只是在账号之上多一层折叠，复用同一份按个人页计算的底层结果。
- 代价是区域维度的历史报表不可复现：移区之后再看上个月的区域数字会变。后台在区域筛选处要写明这一点，否则运营会当成 bug 报上来。
- 移区因此是一个会改动历史报表的动作，不只是改个归属。后台的移区确认要提示这一点。
- 埋点表结构不变，不需要回填，ADR-0006 的纯计次口径也不受影响。
- 若将来确实需要冻结历史，正确的做法是另做一份带区域的月度快照报表，而不是给明细事件加区域列——后者会把恒等式一起改掉。
