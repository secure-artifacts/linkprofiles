# 实心背景从条目级提到页面级

ADR-0011 刚把「长什么样」从 `is_lead` 里拆出来，做成 `buttons.solid_background` —— 每个条目一个开关，视觉与线索语义从此互不干涉。这一版把那个开关**整体挪到了页面上**：`profiles.solid_background`，全页要么都实心，要么都描边。

一轮之内反转一个刚做的决定，值得记清楚为什么。

## 拆开是对的，逐条配是多余的

ADR-0011 解决的问题是**耦合**：`is_lead` 一个字段同时管「算不算线索」（埋点口径）与「实心还是描边」（视觉），改一个必然动另一个。这个诊断没错，这次也没有回退——`is_lead` 仍然只管线索。

错的是解法里附带的那个假设：既然要拆，就顺手给了用户逐条控制的粒度。实际用起来才发现，**逐条控制解决的不是用户的问题**。用户想要的是「这一页看起来是什么风格」，不是「第三条和第七条要不要不一样」。混排出来的页面并不显得有层次，只显得没排版好——十条条目里三条实心七条描边，读起来像是没配完。

真正用来分级的手段一直是**顺序**：重要的排前面。这与「不分组、无区段标题」那条既有决定是一脉相承的——分级靠位置，不靠给每一行单独挑长相。

## 顺带把「图标白底」也放在页面级

品牌图形背后那枚白色衬底原本是写死的。这次一并做成开关，放在同一个地方、同一个粒度。理由一样：它是页面的风格取向，不是某一条的属性。

两个开关**相互独立**：描边行可以带白底，实心卡片也可以不带。没有把它们合成一个「风格」枚举，是因为四种组合都有人会想要，合成枚举只会逼着用户在四个起不好名字的选项里挑。

## Consequences

- 迁移 `0012`：`profiles` 加两列，`buttons` 删一列。删列放在最后一步（与 0010 把 `DROP TABLE social_icons` 放在文件末尾同一条纪律）。
- **存量一律回填成描边**（`solid_background` 默认 `false`），不做「按每页多数条目投票」那种保留现状的尝试。统一之后必然有一半要变样，投票只是把「变哪一半」搞得更难预测；页面总数很少，用户在后台一勾就能改回来。
- `icon_plate` 默认 `true` —— 白底是改动前的现状，默认开着才让迁移当天页面不跳变。
- `ButtonList` 不再逐条判断，整列一次选定 `SolidCard` 或 `OutlineRow`；`ButtonView` 上少一个字段。
- **`migration-0010.test.ts` 必须收窄到 `upTo: '0010'`**。它原本跑完整条迁移链，0012 删掉那列之后，里面「`solid_background` 按 `is_lead` 回填」的断言会直接查不到列。0010 当时确实回填正确，这是那一刻的事实，断言该留着——只是它的测试范围本来就该停在 0010，不该顺带跑完后面所有迁移。

## 关掉图标白底会让一部分图形看不见

品牌图形的颜色是构建期烧进 `fill` 的注册品牌色，**不跟主题走**。白底开着时它们永远压在 `#fff` 上；关掉之后，底色就成了「品牌色 × 主题」的自由组合。

`x`、`threads`、`tiktok` 三个平台的图形是纯黑的（`#000000`）。实心卡片下它们压在 `--surface` 上，`slate` 主题的 surface 是近黑；描边行下直接压在页面渐变上，`harbor` / `moss` / `ember` / `nocturne` 四套都偏暗。**六套主题里五套会中招**，而且不是「差一点」——对比度掉到 1.2:1 以下，等于和底色融成一片。

处理方式沿用本项目对低对比度一贯的态度（背景遮罩也允许用户调到任意危险值，只提示不拦）：

- `icon-plate.test.ts` 把哪几组会出事**记录下来**，不是门禁。品牌色改了、主题改了，这份清单会跟着变，届时提示文案该一起复核。
- 后台那个开关旁挂了 caveat 文案，让用户带着信息选。
- **不做**「按主题自动强制打开白底」的运行时兜底：那会让这个开关在某些主题下变成摆设，也正是 ADR-0011 刚拆掉的毛病——视觉决策被别的东西偷偷接管。

写这组测试时顺带查出一个**本来就存在**的问题：Snapchat 的黄（`#FFFC00`）压在白衬底上只有约 1.1:1，那枚幽灵图形在白底开着的时候就几乎看不见。这与本次改动无关，记在测试里是为了别把它误当成关白底带来的新问题。
