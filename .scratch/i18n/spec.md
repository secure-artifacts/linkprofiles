# 多语言支持

Status: ready-for-agent

## 问题陈述

后台界面、服务端报错和公开个人页上的固定文案全部是硬编码中文，没有任何切换机制。菲律宾等地区的账号持有者已经在使用本系统，他们看不懂后台的每一个按钮、每一条校验提示和每一句删除确认，只能靠猜或者靠归属管理员转述来操作。

具体表现：

- 账号持有者进后台改自己的个人页，编辑器里的字段名、社媒入口的输入提示、删除个人页的后果说明全是中文。这些恰恰是最需要读懂的地方，因为删除个人页不可逆。
- 表单填错时服务端返回中文报错，界面原样显示，用户不知道自己错在哪。
- 公开个人页无论内容是什么语言，HTML 都声明 `lang="zh"`。菲律宾语简介的页面被浏览器和屏幕阅读器当成中文处理，会误弹翻译提示，读屏发音也是错的。
- 分析页的国家名、日期格式一律按中文习惯渲染。
- 外部调用方通过联系方式更新 API 拿到的报错也是中文。

## 解决方案

引入两个新的领域概念，并把全站文案接入 i18next。

**界面语言**属于账号，决定这个人在后台看到的一切文字，以及服务端返回给他的报错语言。用户自己可以改，归属管理员按现有归属规则也可以替名下用户改。

**页面语言**属于个人页而不属于账号，由所有者设定，决定公开页的 HTML 语言声明和页面上那几条固定文案。一个账号名下的多个个人页可以各自是不同语言。页面语言不跟随访客的浏览器语言，理由见 ADR-0020。

首批支持七种语言：英语、简体中文、菲律宾语、西班牙语、巴西葡萄牙语、印尼语、越南语。英语是源语言，任何语言缺译文时回落到英语。

用户内容（显示名、简介、条目标题与描述）保持单一版本，不做按访客语言切换的多语言版本。

## 用户故事

1. 作为菲律宾的账号持有者，我希望后台界面显示菲律宾语，从而不必靠猜就能独立完成日常操作
2. 作为账号持有者，我希望在设置里切换界面语言，从而在系统猜错时自行纠正
3. 作为账号持有者，我希望切换语言后换一台设备登录仍是同一种语言，从而不用每台机器重设一次
4. 作为账号持有者，我希望表单校验失败时的提示是我的界面语言，从而知道具体哪个字段不合格
5. 作为账号持有者，我希望删除个人页的二次确认文案是我的界面语言，从而理解这个操作不可逆
6. 作为账号持有者，我希望修改 short_name 的确认提示是我的界面语言，从而明白已发出的旧链接会失效
7. 作为账号持有者，我希望添加社媒入口时的输入提示是我的界面语言，从而填对号码格式而不是反复被打回
8. 作为账号持有者，我希望给每个个人页单独设定页面语言，从而用一个账号运营面向不同市场的多个个人页
9. 作为账号持有者，我希望新建个人页时页面语言默认跟我的界面语言，从而多数情况下不必额外设置
10. 作为账号持有者，我希望页面语言与界面语言互不牵连，从而可以用菲律宾语后台管理一个西班牙语个人页
11. 作为账号持有者，我希望切换界面语言后分析页的国家名跟着变，从而看懂访客来自哪里
12. 作为账号持有者，我希望日期显示成无歧义的格式，从而不会把某月某日读反
13. 作为访客，我希望个人页的语言声明与页面上的实际文字一致，从而浏览器不再误弹翻译提示
14. 作为使用屏幕阅读器的访客，我希望页面语言声明正确，从而读屏用正确的发音规则朗读简介
15. 作为访客，我希望头像视频的静音按钮有我看得懂的无障碍标签，从而知道点它会发生什么
16. 作为访客，我希望访问不存在的地址时看到英语的提示页，从而理解这是地址错了而不是站点故障
17. 作为访客，我希望分享个人页到社媒时卡片文案稳定，从而不会因为抓取方的请求头不同而生成不同的卡片
18. 作为归属管理员，我希望在后台看到名下每个账号的界面语言，从而在对方求助时知道他看到的是什么界面
19. 作为归属管理员，我希望替名下账号修改界面语言，从而在对方被锁在看不懂的界面里时帮他改回来
20. 作为归属管理员，我希望批量开号时新账号自动继承我的界面语言，从而给同一地区的一批用户开号不必逐个设置
21. 作为归属管理员，我希望自己的后台也能切换语言，从而管理多地区用户时用自己习惯的语言工作
22. 作为超级管理员，我希望升级后所有存量账号和个人页保持原样，从而老用户感知不到这次改动
23. 作为超级管理员，我希望新部署初始化出的超级管理员是英语，从而在没有任何上下文时得到一个可预期的结果
24. 作为超级管理员，我希望跨账号的个人页排行对所有人顺序一致，从而与他人核对数据时不会出现顺序分歧
25. 作为外部系统的开发者，我希望联系方式更新 API 的报错是英语，从而不必处理中文字符串
26. 作为外部系统的开发者，我希望继续按结构化的错误码判断失败原因，从而报错文案的语言变化不影响我的集成
27. 作为未登录的用户，我希望登录失败提示是英语，从而在还没有账号语言可依据时也能读懂
28. 作为开发者，我希望新增一条文案时漏补某种语言会被自动发现，从而不会静默漏译上线
29. 作为开发者，我希望文案 key 拼错时类型检查直接失败，从而不用等到界面上出现原始 key 才发现
30. 作为开发者，我希望译文集中在一个包里，从而交给译者时能指出明确的交付范围
31. 作为开发者，我希望后台只下载当前语言的译文，从而语言数量增长不会拖慢首屏
32. 作为译者，我希望以英语为源文对照翻译，从而不需要具备中文能力
33. 作为运营方，我希望以后加入新语言只是往目录里添文件，从而扩语言不需要改代码

## 实现决策

**新增 i18n 包**。放在依赖链最底层，`shared`、`profile-ui`、`server`、`admin` 都可以依赖它。它导出 i18next 实例工厂、支持的语言标签常量、语言标签协商函数，以及七份译文目录。译文按命名空间拆分，后台文案、公开页文案、服务端报错各一个命名空间，消费方只加载自己需要的那份。

**语言标签取值**为 `en`、`zh-Hans`、`fil`、`es`、`pt-BR`、`id`、`vi`。这七个值同时用于两个新数据库列、HTML 语言声明、`Accept-Language` 协商结果和 Intl 的 locale 参数，四处必须是同一套写法。菲律宾语用 `fil` 而不是 `tl`，因为 CLDR 中两者是不同的数据集。

**源语言与回落**。英语是源文，key 采用语义标识而非中文原文或编号。任何语言缺某条译文时回落到英语，不回落到中文。

**账号表新增界面语言列**。非空，存量行迁移时一律填 `zh-Hans`。新建账号时写入创建者的界面语言；由 bootstrap 流程创建的超级管理员没有创建者，填 `en`。批量开号继承操作者的界面语言，不改批量开号的输入格式。

**个人页表新增页面语言列**。非空，存量行迁移时一律填 `zh-Hans`。新建个人页时写入所有者的界面语言。页面语言属于个人页，与 short_name 一样按个人页计数，不按账号计数。

**权限沿用现有归属规则**。修改界面语言与页面语言都走已有的目标用户加载与归属校验，管理员只能操作名下用户，超级管理员不受限。不新增权限概念。

**服务端语言判定**。后台前端在每个请求上带 `Accept-Language`，值取自当前账号的界面语言。服务端据此选择报错语言。拿不到有效语言时一律英语，覆盖三种场景：个人页不存在的 404 页、登录尚未成功时的报错、外部联系方式更新 API 的报错。服务端使用固定实例配合按语言取出的翻译函数，不为每个请求新建 i18next 实例。

**公开页渲染**。HTML 语言声明取自该个人页的页面语言，同时输出对应的 og locale。页面上的固定文案按页面语言渲染，包括头像视频静音按钮的无障碍标签、Banner 图的替代文本、显示名为空时的标题回落和简介为空时的描述回落。公开页保持零 hydration，译文在服务端渲染时就已确定，不下发任何客户端语言逻辑。不做 hreflang，因为同一个个人页没有平行语言版本。404 页固定英语，它没有对应的个人页可以取语言。

**枚举文案归属**。品牌专有名词继续作为结构化数据留在社媒平台清单里，七种语言下写法相同。需要翻译的描述性文案改为 key 由消费方翻译，包括社媒入口的输入提示、非品牌的平台名、来源标签中的直接访问与未标记、未知国家与其他。分析查询中把已删除条目的中文占位改成返回空值，由前端渲染占位文案。

**后台改造**。全部内联中文文案抽成 key。译文按语言动态加载，只拉当前语言那一份，切换语言时再拉新的。语言切换入口放在顶栏账号菜单，页面语言选择器放在编辑器中与布局、主题同一区域。

**格式化规则**。日期一律渲染为 ISO 形式的年月日，避免七种语言之间日月顺序的歧义。数字与国家名按当前界面语言格式化。所有用于排序的字符串比较改为固定的中立比较，不受界面语言影响，保证不同语言的人看到同一个排行顺序。

**约束**。服务端产物被打成单文件，运行时没有可靠的包目录可读，因此译文必须是可静态 import 的模块，不能走文件系统加载。这与现有的公开页 CSS 固化成模块是同一个理由。

## 测试决策

好的测试只断言外部可观察的行为：HTTP 响应的状态码、响应体、渲染出的 HTML 属性与文字，以及纯函数的输入输出。不断言 i18next 内部结构、不断言某个组件调用了翻译函数、不快照整页 HTML。

沿用三个现有接缝，不新建接缝。

**HTTP 接缝**，用现有的测试上下文与应用注入方式，与既有的路由测试同构。覆盖：

- 页面语言为菲律宾语的个人页渲染出对应的语言声明与固定文案
- 同一个个人页对不同 `Accept-Language` 的请求返回相同的语言声明，证明页面语言不跟随访客
- 地址不存在时返回的提示页固定为英语
- 带不同 `Accept-Language` 的失败请求返回对应语言的报错，未携带或不受支持时返回英语
- 登录失败的报错固定为英语
- 外部联系方式更新 API 的报错固定为英语，且结构化错误码不随语言变化
- 社媒平台清单接口返回 key 与品牌数据，不再返回中文描述
- 分析接口对已删除条目返回空值而非中文占位
- 修改界面语言与页面语言时的归属校验，管理员改不了非名下账号

**纯函数接缝**，在新 i18n 包内测试，先例是社媒平台与主题的既有单测。覆盖：

- 七份译文的 key 集合与英语源文完全相等，且没有空串
- 语言标签白名单只接受这七个值
- `Accept-Language` 协商：命中、带权重、带地区后缀降级、完全不支持时回落英语

**迁移接缝**，先例是既有的两个迁移测试。覆盖：存量账号与个人页在迁移后都拿到 `zh-Hans`，且两列非空。

后台不建测试接缝。它目前没有任何测试基础设施，本次不引入。后台文案的正确性由 key 的类型约束与译文对齐测试兜底。

## 范围外

- **用户内容的多语言版本**。显示名、简介、条目标题与描述保持单一版本，不按访客语言切换。这需要改数据库结构、编辑器交互和埋点维度，量级超过本规格全部内容之和。
- **RTL 布局**。不支持阿拉伯语、希伯来语等从右到左的语言。四种公开页布局与后台的方向相关样式都需要改造，属于布局级改动。
- **CJK 展示字体**。自托管的展示字体只有拉丁子集，中文标题回落系统字体是升级前就存在的现状，本次不处理。
- **按语言维度的数据分析**。不新增按界面语言或页面语言拆分的分析视图。
- **外部联系方式更新 API 设置页面语言**。该 API 继续只管联系方式。
- **访客语言的埋点采集**。不记录访客的 `Accept-Language`。
- **超出七种的语言**。以后加语言只需往译文目录添文件，不在本规格范围内。

## 补充说明

七份译文由实施方产出。菲律宾语是这次需求的起因，建议上线后找一位母语使用者复核那一份。

两条 ADR 记录了本规格中最难回退的两个决定：页面语言属于个人页而非跟随访客，以及英语作为源语言配合语义 key。实施时如果要偏离，先改 ADR。

术语按 `CONTEXT.md` 使用：界面语言、页面语言、内容语言三者不得混用，尤其不要用"语言设置"这种含糊说法同时指代前两者。
