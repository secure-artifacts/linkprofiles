# 05：自助注册

**构建内容：** 拿到邀请码的人自己完成开户。他在后台的注册页填账号、密码、邀请码和 short_name，输入码之后页面告诉他将加入哪个区域，输入 short_name 时当场知道有没有被占。提交后一次建出账号和他的第一个个人页，跳回登录页，登录进去就有一个能编辑的个人页。超级管理员随时可以一键关停全站注册。

**阻塞项：** 04 邀请码生成与重置；多语言支持（`.scratch/i18n/`）合并完成。开工前先确认多语言的接口错误返回形态已定型，本票新增的匿名接口要沿用同一套约定，注册页文案也要接进同一套多语言方案。

**状态：** ready-for-agent

- [x] 注册页是后台这个 SPA 的一个新路由，与登录页共用同一套组件，不新增服务端渲染路径
- [x] 匿名接口：用邀请码换区域名，供注册页做「你将加入 XX」的确认
- [x] 匿名接口：提交注册，在一个事务里建出账号与它的第一个个人页
- [x] short_name 走既有的冲突判定，含墓碑；并发抢注导致整单失败时提示用户重填
- [x] 账号重复、short_name 重复、short_name 撞墓碑分别给出可区分的原因
- [x] 密码有最低长度要求，与既有规则一致
- [x] 无效码、无归属区域的码都拒绝注册
- [x] 注册成功后跳回登录页并告知可以登录，不自动发会话
- [x] 账号注册即可用，不经审核
- [x] 全站设置新增注册总闸，只有超级管理员改得了，与来源透传默认值并列
- [x] 总闸关闭时注册页与两个匿名接口都明确拒绝，且不影响已有用户登录与使用

## 备注

- 注册总闸默认**关着**，开放是一次显式的决定。
- short_name 的实时占用检查挂在 `register/preview` 上，必须先有一个有效邀请码
  才问得了 —— 不额外开一个任何人都能拿来枚举地址的匿名探针。
- 未登录分支没有 router，注册页靠 `location.pathname` 判断并用 `history.pushState`
  切换，`/_admin/register` 因此是个发得出去的链接。
