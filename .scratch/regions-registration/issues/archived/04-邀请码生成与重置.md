# 04：邀请码生成与重置

**构建内容：** 每个区域在区域页上有一个可以直接复制的邀请码。管理员能重置它，重置后旧码立刻失效、新码可用，而已经用旧码注册进来的人归属不变。想要好记的码时也可以自己写一个。

这张票只做码的产生与管理，用码注册是下一张。

**阻塞项：** 03 区域页与增删改；多语言支持（`.scratch/i18n/`）合并完成。

**状态：** ready-for-agent

- [x] 邀请码表落地：挂在区域下（区域删除时级联）、码值全站唯一、带是否有效
- [x] 一个区域可以先后挂多个码，同一时刻至多一个有效
- [x] 重置的实现是旧码置为无效加插入一条新的有效码，不是原地覆盖，码与区域的历史对应关系保留
- [x] 接口与界面上任一时刻只呈现当前有效的那一个码
- [x] 系统生成的码为 8 到 10 位大写字母与数字，剔除容易看混的 O、0、I、1
- [x] 归一化规则：去空白、转大写后入库与比对
- [x] 管理员可以传入自定义码，走同一套字符集与长度约束
- [x] 自定义码与已有码撞车时拒绝并说明原因
- [x] 格式校验与归一化放在 `shared` 里，server 与 admin 共用同一份判断
- [x] 纯函数测试覆盖字符集、长度边界、去空白与转大写、易混字符的剔除、非法输入
- [x] 区域页能复制码、能重置码

## 备注

- 「同一区域同时至多一个有效码」由部分唯一索引保证，不靠应用层自觉。
- 重置在一个事务里作废旧码再插新码；撞车时整个事务回滚，旧码不会被白白作废。
- 码用 `crypto.getRandomValues` 加拒绝采样生成，不用 `Math.random`——码是注册的
  唯一凭据，可预测的伪随机等于把闸门敞开。
- 迁移 0020 建出来的那批默认区域没有码（SQL 里没有密码学安全的随机源，不愿意
  用 `random()` 凑），后台显示「还没有码」，管理员点一次重置即可拿到。
