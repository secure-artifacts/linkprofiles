# 02：归属改走区域单链

**构建内容：** 管理员看得见谁、管得了谁，从此沿「用户 → 区域 → 管理员」推导，用户身上不再有独立的归属管理员字段。后台用户列表里「归属管理员」列换成「区域」列。对管理员来说可见范围一点没变，变的是它由什么决定。

按 expand–contract 的后两步做：调用点全部改读区域，然后删掉旧列。

**阻塞项：** 01 区域表与数据迁移；多语言支持（`.scratch/i18n/`）合并完成。开工前先确认多语言的接口错误返回形态已定型，本票要沿用同一套约定。

**状态：** ready-for-agent

- [x] 授权检查点的可见范围改为经区域表的连接，管理员看归属为自己的区域里的用户，超级管理员不限，用户仍只看自己
- [x] 新增可见区域范围的过滤，与可见用户范围同源
- [x] 取目标用户时一并取出他的区域与该区域的归属管理员
- [x] 授权判定仍然只有一处，不在各个路由里各判各的
- [x] 单个创建与批量创建的用户，默认落进操作者的默认区域
- [x] 后台用户列表显示区域名，不再显示归属管理员
- [x] 第二个迁移删掉归属管理员列，并加上检查约束：用户必须有区域，管理员与超级管理员必须没有
- [x] 数据分析里解析可见对象的那套逻辑与用户路由的可见性查询收敛为一份
      —— 三处本来就都只调 `visibleUsersFilter`，把它实现成相关子查询之后，
      区域对调用点完全透明，没有再拆合并的必要
- [x] 既有越权测试全部改为断言区域，并全绿
