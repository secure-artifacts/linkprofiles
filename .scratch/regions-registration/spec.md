# 区域与邀请码自助注册

Status: ready-for-agent

## 问题陈述

现在开一个账号只有一条路：管理员在后台逐个填账号、密码、用户名称和 short_name，或者从表格粘一批进批量创建。系统当初就是按内部自用设计的，ADR-0005 开篇写的是「系统是内部自用、无公开注册的」。

现在有几千人排队等开户。逐个建不成立了，粘表格也只是把工作量从点击变成了整理表格，而且整理表格的人还得先收齐所有人的账号和密码。

同时暴露出第二个问题：现有的分权只有一层，用户直接挂在创建他的管理员身上。一个管理员手里几百上千个用户全在一个平面里，既没法按批次分开管理，也没法在数据分析里回答「我这批人表现怎么样」——只能一个账号一个账号地看，或者看自己名下的全量汇总，中间没有任何层级。

## 解决方案

引入**区域**作为用户的归属单位，并开放凭**邀请码**的**自助注册**。

每个用户恰好属于一个区域，每个区域属于一个管理员。管理员建区域、给区域生成邀请码、把码发给要注册的人；拿到码的人自己在注册页填账号、密码和 short_name，一次就建出账号和他的第一个个人页，落地即可用，不经人工审核。他落进哪个区域由这个码决定。

原来挂在用户身上的归属管理员字段撤掉，可见范围改为沿「用户 → 区域 → 管理员」这条单链推导。管理员只看得见自己名下的区域与其中的用户，超级管理员不受此限，与今天的分权语义一致，只是中间多了一层。

数据分析里，区域成为最外层的可选筛选：不选就是自己全部可见区域的汇总，选一个就只看那个区域，再往下才是账号和单个个人页。管理员也可以把用户从一个区域**移区**到另一个。

## 实现决策

### 数据模型

新增两张表，各自一个文件放进 `shared` 的 schema 目录。

**区域表**：主键、名称、归属管理员外键（可空，指向管理员被删时置空）、是否默认区域、创建与更新时间。名称全站唯一，因为它会在注册页展示给注册者，两个同名区域会让人分不清进了哪个。归属管理员为空即**无归属区域**。

**邀请码表**：主键、区域外键（区域删除时级联）、码值、是否有效、创建时间。码值全站唯一。一个区域可以先后挂多个码，但同一时刻至多一个有效——这是数据模型上的多对一，接口与界面上只呈现当前有效的那一个。重置的实现是把旧码置为无效、插入一条新的有效码，不是原地覆盖，这样码与区域的历史对应关系仍在。

**账号表**改动：删掉归属管理员外键，新增区域外键。区域外键在列上可空，用一个检查约束表达真正的规则——`role = 'user'` 时必须有区域，管理员与超级管理员必须没有。区域外键在区域被删除时限制而非级联，配合「区域需先清空才能删」这条规则形成双保险。

### 迁移

手写数据搬迁，按 CLAUDE.md 的要求配一个 `migration-*.test.ts`。顺序是：

1. 建区域表与邀请码表
2. 插入唯一的一个「未分配」区域，主键固定，归属为空。**它由迁移创建而不是由 bootstrap 创建**，因为 `bootstrapSuperadmin` 在 `index.ts` 里跑、`buildApp` 不经过它，挂在那里测试上下文就没有这个区域。放在迁移里，全新安装、存量升级、测试上下文三条路径拿到的是同一个东西。
3. 为每个 `role = 'admin'` 的账号插入一个默认区域，名称取该管理员的用户名称，为空则取账号，与已有名称冲突时追加序号
4. 账号表新增区域外键列
5. 把 `role = 'user'` 且归属管理员是某个管理员的用户，写进该管理员的默认区域
6. 把剩下的 `role = 'user'`（原本无归属的，以及归属指向超级管理员的）写进「未分配」区域——超级管理员不拥有区域，他建的用户没有对应的默认区域可去
7. 删掉归属管理员列，加上检查约束

验收标准是：迁移前后每个用户对每个管理员的可见性逐人一致。

### 授权

`policy.ts` 仍是唯一授权检查点，不在各个 handler 里各判各的。

- `visibleUsersFilter` 从单字段等值改为经区域表的一次连接：管理员看归属为自己的区域里的用户，超级管理员不限，用户仍只看自己。
- 新增一个可见区域范围的过滤，与上面同源。
- `canTouchUser` 取目标用户时一并取出他的区域与该区域的归属管理员。
- 能力清单新增区域的建、列、改、删与邀请码管理。管理员持有前四项对自己名下区域的权限；`user:assign` 的语义从「指派归属管理员」变为「跨管理员移区」，仍然只有超级管理员持有。
- 管理员移区的目标区域必须也归属于他自己，否则拒绝。

### 接口

系统路径继续带下划线前缀（ADR-0003）。

- 区域的增、列、改、删挂在 `/_api/regions`。列表返回名称、归属管理员、是否默认、成员数与当前有效邀请码。删除时若不是空区域或是默认区域，返回冲突而非静默处理。
- 邀请码重置挂在区域下，可选带自定义码值；不带则系统生成。
- 移区替换掉现有的指派归属管理员接口，接受单个或多个用户 id。
- 注册相关两个匿名接口：一个用邀请码换区域名供注册页确认，一个提交注册。两者都受全站注册总闸控制。
- 分析接口新增区域筛选参数，与既有的账号、个人页参数构成层层收窄的关系，同时指定时以最内层为准。
- 全站设置新增注册总闸开关，只有超级管理员改得了，与来源透传默认值并列在同一张单行表里。

### 注册流程

注册页是 admin 这个 SPA 的一个新路由，与登录页共用同一套 Tailwind + Radix 组件（ADR-0007），不新增服务端渲染路径，因此不触及 ADR-0004 对公开页零 hydration 的约定。

提交后服务端在一个事务里建出账号和它的第一个个人页，与批量创建同一条规则。short_name 走既有的冲突判定（含墓碑），并发抢注导致整单失败时用户重填。成功后跳回登录页，不自动发会话。

注册不经审核，账号立刻可用。

### 邀请码格式

生成规则与校验规则都放进 `shared` 的校验目录，与 short_name、账号的校验并列，因为 server 与 admin 都要用同一份判断。

- 系统生成：8 到 10 位，大写字母与数字，剔除容易看混的 O、0、I、1
- 归一化：去空白、转大写后入库与比对
- 自定义：同一套字符集与长度约束，全站唯一

### 后台界面

- 新增一个与用户、管理员并列的**区域**页，管区域与邀请码：列表带成员数与当前码，支持建、改名、删、重置码、复制码
- 用户页新增区域列、区域筛选与批量移区；建用户与批量建用户的表单新增区域选择
- 分析页新增最外层的区域筛选器，位置在账号筛选之前
- 管理员页新增每人的区域数
- 设置页新增注册总闸
- 登录页旁新增注册页路由

### 分析

区域按用户**当前**所属区域计算，埋点事件与日汇总都不冗余区域字段（ADR-0019）。实现上先按个人页算出统一表现，再依次折叠成账号行与区域行，保证四层口径一致。区域筛选处要写明「移区后历史区域数字会变」。

## 测试决策

好的测试只断言外部可观察的行为——接口的状态码与响应体、迁移后数据库里的事实、纯函数的输入输出。不断言内部调用顺序，不断言某个函数被调过，不 mock ORM。

沿用三个已有接缝，不新增第四个。

### HTTP 接缝（主接缝，规格验收就在这一层）

用 `app.inject()` 走完整 Fastify 管线，`createTestContext` 起独立 schema，`factories` 造数据，`login` 与 `withSession` 拿会话。先例是 `ownership.test.ts`、`roles-users.test.ts`、`analytics.test.ts`。

`factories.ts` 需要扩展：造账号时能指定区域，并提供造区域与造邀请码的工厂。既有调用点不传区域时应落到「未分配」区域，避免逐个改所有测试文件。

要覆盖的行为：

- 注册：正确的码建出账号与首个个人页；错码拒绝；总闸关闭时拒绝；账号重复、short_name 重复、short_name 撞墓碑分别拒绝并给出可区分的原因；密码过短拒绝；无归属区域的码拒绝
- 邀请码换区域名：有效码返回区域名，无效码不返回
- 区域增删改：管理员建的区域归属自己；改名；名称重复拒绝；删空区域成功；删非空区域拒绝；删默认区域拒绝
- 邀请码：重置后旧码失效、新码可用；已用旧码注册的人归属不变；自定义码重复拒绝；生成的码符合格式
- 越权：管理员看不见也改不动别的管理员的区域；管理员移不动用户到别人的区域；跨管理员移区只有超级管理员做得了；管理员看不见无归属区域
- 管理员删除：其名下区域变成无归属；这些区域的码立即失效；超级管理员重新指派后可重新启用
- 移区：单个与批量都生效；移区后该用户的历史数据立刻计入新区域
- 分析：不带区域参数时等于全部可见区域之和；带区域参数时只含该区域；区域指标等于其中全部账号指标之和；指名一个看不见的区域与「不存在」同一个响应
- 设置：只有超级管理员改得了注册总闸

### 迁移接缝

先例是 `migration-0010.test.ts` 与 `migration-0014.test.ts`：raw postgres 客户端、`applyMigrations` 带 `upTo` 停在旧版本、按旧结构插数据、再迁到新版本、断言搬迁结果。

要覆盖：归属于管理员的用户落进该管理员的默认区域；无归属用户落进「未分配」；归属指向超级管理员的用户落进「未分配」；每个管理员恰好一个默认区域；默认区域重名时追加序号；迁移前后逐人可见性一致。

### 纯函数接缝

先例是 `packages/shared/src/validation/short-name.test.ts` 与 `account-name.test.ts`。新增邀请码的格式校验与归一化测试：字符集、长度边界、去空白与转大写、剔除易混字符、非法输入被拒。

## 范围外

以下明确不做，需要时另开规格：

- **邀请码名额上限**。表里不预留字段，需要时再迁一次。
- **注册与登录的限流**。本次不引入任何速率限制插件，登录接口维持现状。
- **邀请码过期时间**。
- **注册审核**。账号注册即可用。
- **用户自助换区**。用户后台不出现区域，也没有申请换区的入口。
- **区域嵌套**。区域是一层，不做树形结构。
- **邀请码使用明细报表**（谁在什么时候用哪个码注册的）。区域成员数够用。
- **注册时的邮箱或手机验证**。注册只要账号、密码、邀请码、short_name。
- **注册页的多语言**。见下。

## 补充说明

### 已知并接受的风险

自助注册是本系统第一个匿名写入口，而本次既不加限流也不做邀请码名额上限。邀请码泄露后没有任何自动止损，唯一手段是超级管理员拉全站注册总闸。具体后果是：泄露的码可以被无限次使用，而被占掉的 short_name 一旦删除就进墓碑永不再分配，这个污染不可逆。允许管理员自定义邀请码进一步扩大了被猜中的可能。

这是明知取舍后的决定，已写进 ADR-0018。若后续要补救，优先级是先做名额上限，再做限流。

### 相关 ADR

- **ADR-0017** 区域取代归属管理员成为唯一归属载体
- **ADR-0018** 开放邀请码自助注册
- **ADR-0019** 区域数据按当前归属计算
- **ADR-0005** 仍然有效，但它「内部自用、无公开注册」的前提作废，归属载体的变化以 ADR-0017 为准
- **ADR-0015** 的分层扩展为四层，恒等式相应扩展
- **ADR-0003**、**ADR-0004**、**ADR-0007** 约束注册页的形态与路径

### 与并行改动的冲突

多语言那份改动正在进行中，已经动了 `routes/` 下几乎全部文件、`auth/guards.ts`、`auth/plugin.ts`，并新增了 `packages/i18n` 与 `packages/server/src/http/`。本规格要改的用户路由、分析路由、设置路由、批量创建路由和授权守卫与它高度重叠。

建议在多语言合并之后再开工，或者至少先确认它的接口错误返回形态已经定型——本规格新增的注册与区域接口需要沿用同一套错误返回约定。另外新增的注册页与区域页的文案也要接进同一套多语言方案，本规格不单独处理。

### 术语

全文使用 `CONTEXT.md` 定义的词：区域、归属管理员、默认区域、无归属区域、邀请码、自助注册、移区、账号、用户名称、short_name、显示名、个人页、线索、点击、页面浏览。「区域」与数据分析里的「国家」毫无关系，前者来自注册时用的邀请码，后者来自访客 IP。
