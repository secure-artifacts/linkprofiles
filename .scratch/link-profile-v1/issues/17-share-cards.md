# 17：分享卡片与收录控制

**构建内容：** 把链接转发到 WhatsApp 或 Facebook 时，对方看到的是带头像和名字的预览卡片而不是一行光秃秃的地址；同时这些页面不会被搜索引擎收录。

**阻塞项：** 09 六套主题、10 媒体上传与处理

**状态：** ready-for-human

- [x] 公开页输出完整 og 标签：标题、描述与预览图
- [x] 预览图取自用户的头像或头图，缺失时回落到与主题一致的占位图
- [x] 输出 noindex 阻止搜索引擎收录
- [x] **noindex 与 og 标签并行不冲突**：社媒爬虫仍能正常抓取卡片
- [x] 爬虫抓取行为不产生埋点记录（与 12 的规则一致）

## Comments

**实现记录（2026-08-27）**

- 「noindex 与 og 并行不冲突」不是巧合而是机制：前者是给搜索引擎索引器读的 `<meta name="robots">`，后者是给社媒爬虫读的 `og:*`，两类爬虫读的是不同标签。测试里直接用 WhatsApp 与 Facebook 的真实 UA 请求，断言 robots 与 og 同时都在、状态码 200。
- **og 里的地址必须是绝对的**，爬虫不解析相对路径。应用只监听 HTTP、前面通常挂一层做 TLS 的反代，所以协议从 `X-Forwarded-Proto` 取，否则卡片里会出现 `http://` 的地址。`PUBLIC_ORIGIN` 配了就以它为准——代理头可以伪造，而这个值会出现在转发给别人的卡片里。**部署时建议显式配上 `PUBLIC_ORIGIN`。**
- 占位预览图输出 **PNG 而不是 SVG**：不少社媒爬虫不认 SVG 的 og:image。由 sharp 从主题渐变现渲染，按主题缓存在内存里，1200×630。
- 显示名与简介进 meta 前做 HTML 转义，`"><script>` 这类内容撑不破标签，有测试守着。
- 加 og 之后 07 的一条测试变红：它在整篇 HTML 上断言不含「联系方式」四个字，而新的 og:description 兜底文案正好带上了这四个字。测试的意图是「按钮列表里没有区段标题」，范围写宽了。已把断言收到 `.pp-body` 那一段内，并顺带断言这段里没有任何 h2–h6。
