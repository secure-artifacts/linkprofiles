# 22：趋势图数据稀疏时整条渲染成一块实心色块

**构建内容：** 数据分析页的「趋势（按天/小时）」图表，不管区间内有几天真的产生过线索，看起来都得像个柱状图——每一天一根柱子，没数据的天是空的，不是把有数据的那几天拉伸到占满整个容器。

**阻塞项：** 无（可立即开始）

**状态：** ready-for-agent

- [ ] 7 天预设下，趋势图固定渲染 7 根柱子（对应 7 个自然日），没有线索的日子柱高为 0，不是从数组里整个消失
- [ ] 30 天预设与自定义区间同理，柱子数量等于区间天数（或小时数，取决于 granularity）
- [ ] 只有 1-2 天有数据时，那几根柱子的宽度和其余空柱子一致，不会被 flex 拉伸占满整个卡片宽度
- [ ] `packages/server/test/analytics.test.ts` 补一个用例：区间内只有一天有数据，断言返回的 `trend` 数组长度等于区间天数而不是 1

## Comments

**发现记录（2026-08-27 浏览器全量走查 · 补测）**

- 今天的 74 项走查里没有一项真正验证过趋势图的「有数据」渲染态——三个批次全程产生的线索都只有 0-1 条，图表全程停在空状态文案「这个区间还没有线索」，没人看过它填充起来是什么样。这是走查方法论的一个漏洞：只做了 DOM 断言（有没有崩溃、能不能重渲染），没有真正拿肉眼看过截图。
- 用户指出这个页面「没有报表」后，补测：往 `lena` 灌了 16 条真实线索（走 `/track/click`，真实浏览器 UA，绕开 `isbot` 检测——第一次用 curl 默认 UA 全被当爬虫吞掉，侧面确认 12 的爬虫过滤在正常工作）。截图见趋势图卡片渲染成一整块顶满宽度的纯色矩形，日期标签 `08-27` 被挤到右下角一小行——完全不像柱状图。
- 根因定位：`packages/server/src/analytics/queries.ts:104` 的 `queryTrend` 直接 `group by bucket`，只返回真实有事件的桶，不做区间内完整日期序列的补零。对照同文件 161 行的 `queryHourlyLeads`，那边是 `const buckets = Array.from({ length: 24 }, () => 0)` 先建好定长数组再拿查询结果覆写——`queryTrend` 缺的正是这一步。
- 前端 `AnalyticsPage.tsx` 里的 `BarSeries` 组件对每根柱子用 `flex: '1 0 18px'`（等分容器宽度），这个假设成立的前提是柱子数量等于区间长度；数组只剩 1 项时，这一项独占 100% 宽度，视觉上就是一块实心色块，不是设计问题，是喂给它的数据本身就没补零。
- 复现：`curl -b <cookie> "http://127.0.0.1:3000/_api/analytics?preset=7d&userId=<uid>"`，观察 `range` 是 7 天区间但 `trend` 数组只有 1 个元素。
