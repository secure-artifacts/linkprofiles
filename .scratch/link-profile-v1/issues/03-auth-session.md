# 03：超级管理员初始化与登录会话

**构建内容：** 运维把账号密码写进环境变量，首次启动系统自动建出超级管理员；重复启动不会重复创建。此后可以用这个账号登录后台，登录状态保持三十天，改密码后旧的登录立刻失效。

**阻塞项：** 01 工程骨架与测试底座

**状态：** ready-for-human

- [x] 首次启动读取环境变量创建超级管理员；库中已存在时跳过，重复启动幂等
- [x] 账号 + 密码可登录；密码以 argon2 哈希存储，任何响应都不回传哈希
- [x] 会话存库，通过 HttpOnly 且带 SameSite 的 cookie 维持，有效期三十天
- [x] 登出后原会话立即不可用
- [x] 修改密码后该账号的全部既有会话失效，需重新登录
- [x] 未登录访问后台受保护接口返回未授权，不泄露资源是否存在

## Comments

**实现记录（2026-08-27）**

- bootstrap 幂等的口径是「库里已有超级管理员就跳过」，**并且不用环境变量去覆盖已有账号的密码**——否则改一次 compose 文件就等于悄悄重置了线上密码。测试同时断言了「没建出第二个账号」和「原密码仍有效、环境变量里的新密码无效」。
- 会话表存的是 cookie 令牌的 sha256，不是令牌本身：库被拖走也换不到可用登录态。有一条测试直接断言明文令牌不出现在 `sessions.token_hash` 里。
- 账号不存在与密码错误返回完全相同的响应体，不透露账号是否存在；未登录访问受保护接口在任何资源查找之前就 401。
- 改密码踢掉该账号**全部**会话，含发起改密码的那一条，因此响应顺带 clearCookie，必须重新登录。
- `requireAuth` 只做「登录了没有」。角色与归属的裁定放在 04 建立的授权检查点里，不在这里散判。
