## Comments

**实现记录（2026-08-27）**

- 预览是一个**独立文档**（vite 的第二个入口 `preview.html`），iframe 加载它。这样一次拿到两样东西：`contentWindow.innerWidth === 375` 的真实移动端视口，以及两套 CSS reset 的隔离——人工核对时直接断言了 iframe 文档里不含任何 `ant-` 前缀的类名。
- 预览 import 的是 `@link-profile/profile-ui` 的 `ProfilePage` 与 `profileCss`，**与服务端直出同一份**，不存在第二套实现。
- 草稿经 `postMessage` 灌入，**没有 debounce**：改一个字那边就跟着动。没走「iframe 直接加载真实页面 URL」那条路——那样每次编辑要重新请求，改一个字闪一下。
- 尚未上传的图片与视频以 `URL.createObjectURL` 的 blob 地址进预览，**保存时才真正上传**，用户在确认满意之前不必先落库。
- 顺带把 10 里写好的浏览器端抽帧接进了 UI：选视频时抽首帧当封面，抽不出来就弹出提示要求手动选一张封面图。

**人工核对结果**（本 ticket 不做浏览器端自动化测试）：登录 → 编辑器 → 改显示名，预览里的名字同步变且数据库未动；同时切换主题与布局，两者都生效；iframe 宽度 375、`scrollWidth` 也是 375、无横向滚动；iframe 文档内无 antd 样式渗入。

**核对时抓到一个真 bug 并已修**：草稿更新原来基于闭包里那份 `draft` 合并，同一个事件循环里发生两次更新时后一次会覆盖掉前一次——同时改主题和布局只有一个生效。改成函数式更新（`setDraft(prev => …)`）后两者都生效。

**本 ticket 顺带补齐的后台界面**（tickets 04/05/06/13/14 的验收里隐含要 UI，此前只实现到接口层）：登录页、用户列表（含无归属的红色标记与重新指派下拉）、新建用户、批量创建（失败行带行号与原因）、管理员管理、全站设置（透传默认值 + 已知取舍文案）、数据分析（指标、趋势图、24 小时分布、五个维度拆分、按钮点击率、时区与区间切换）。图表用一排 div 拼的——后台严格用 Ant Design 而 antd 不带图表，为两张柱状图引一个图表库不划算。
