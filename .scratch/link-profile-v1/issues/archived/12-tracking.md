# 12：埋点写入

**构建内容：** 从此每一次页面被打开、每一个按钮被点击都会被记下来，并且带上访客来自哪个国家哪座城市、用什么设备。社媒爬虫来抓分享卡片不会被算成访问，否则页面越受欢迎数据反而越难看。

**阻塞项：** 02 个人页最小可访问

**状态：** ready-for-human

- [x] 公开页每渲染一次写入一条页面浏览；每次点击写入一条点击记录
- [x] **不做任何访客去重，全部纯计次**
- [x] 按 User-Agent 识别爬虫，识别为爬虫则**直接不写记录**；页面与 og 标签照常返回
- [x] IP 先用于查出国家与城市，**随后立即截断再落库**：IPv4 去掉最后一段，IPv6 去掉后 80 位
- [x] 顺序不可颠倒：截断必须发生在地域查询之后
- [x] 解析 User-Agent 得到设备类型与操作系统并落库
- [x] IP 截断与 User-Agent 解析实现为 shared 包内的纯函数，各有覆盖边界情况的单元测试
- [x] 点击记录关联到具体按钮或社媒图标，并标明是否计入线索

## Comments

**实现记录（2026-08-27）**

- 「先查地域再截断」的顺序在 `collectVisitorFacts` 里是一条直线：查完 `lookupGeo(fullIp)` 才 `truncateIp(fullIp)`，完整 IP 只是个局部变量，从不返回也从不落库。测试用一个假的地域解析器记录它实际收到的 IP，同时断言「查询拿到的是完整 IP」与「落库的是截断值且地域没丢」——顺序颠倒这条测试就红。
- 地域解析做成**注入到 buildApp 的依赖**而不是模块级单例，测试因此不需要给源码开后门。
- **GeoLite2-City 库文件不在仓库里**（MaxMind 要求各自申请 license key 后下载）。`GEOLITE2_CITY_PATH` 没配或文件打不开时，地域维度为 null、其余埋点照常写入——少一个维度好过整条记录丢掉，有测试守着这条降级路径。**部署前需要运维下载库文件并配好这个环境变量，否则国家/城市维度一直是空的。**
- 点击的归属与 `is_lead` 一律以库里为准，不信客户端传来的，否则任何人都能往别人的页面刷线索。落库时把当时的 `is_lead` 定死，用户事后改标记不影响历史数据，两条都有测试。
- 埋点表**不设指向 users 的外键**：用户删除后埋点要保留，历史汇总不断档（16 的要求）。
- 客户端用 `sendBeacon`，页面跳走之后请求仍然发得出去，不拦截这次点击；不支持时退回 `fetch(keepalive)`。接口一律回 204，不告诉调用方这个 id 存不存在。
