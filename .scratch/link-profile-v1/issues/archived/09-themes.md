# 09：六套主题

**构建内容：** 用户可以在六套配色之间切换，让页面符合自己的调性。任何一套套在任何一种布局上，文字都看得清。

**阻塞项：** 08 五种布局

**状态：** ready-for-human

- [x] Dawn、Harbor、Moss、Ember、Slate、Nocturne 六套主题全部可用，后台可切换并持久化
- [x] 主题实现为一组 CSS 变量取值，结构不变；**圆角是主题的一部分而非全局常量**
- [x] 三十种布局与主题的组合逐一验证文字对比度达到 WCAG AA
- [x] 新账号默认使用 Dawn·晨
- [x] 用户可上传背景图：上传后覆盖主题的背景渐变，主题的按钮色与文字色仍生效
- [x] 背景图上叠一层暗度可调的遮罩，默认四成，保证文字对比度

## Comments

**实现记录（2026-08-27）**

- **主题令牌只有一个来源**：`packages/profile-ui/src/themes.ts`。`scripts/build-css.mjs` 从这张表生成 `src/generated/themes.css` 再交给 tailwind 编译，对比度测试读的也是同一张表。原来 CSS 里那六个硬编码的主题块已删除——否则 CSS 与测试早晚各说各话。
- 三十种组合逐一验证：不是简单跑六次。布局不决定配色，但决定文字落在渐变的哪一截（Hero 的名字压在 `--bgend` 上、其余压在渐变前段），测试里 `TEXT_BACKDROP` 就是这张对应表，五种布局 × 六套主题共 30 条用例，全部达到 WCAG AA（正文 4.5:1，次要文字 3:1，卡片文字压卡片底 4.5:1）。
- **遮罩的作用方向对两类主题相反**，这一点值得记下来：遮罩只会把图压暗，因此对浅色文字主题（Harbor / Moss / Ember / Nocturne）越深越清楚，对深色文字主题（Dawn / Slate）反而越压越糊。这正是「暗度可调」而不是写死四成的原因，后台的滑块旁边应当把这条说清楚。已用一条测试锁住这个方向性。
- 背景图接管背景后，主题的 `--surface` / `--on-surface` / `--text` / `--r` 全部照旧生效，有测试断言 harbor + 背景图时按钮底色仍是 harbor 的。
- 已在 375px 视口人工核对 Nocturne·夜，与设计稿令牌一致。
