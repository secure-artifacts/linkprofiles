# 10：媒体上传与处理

**构建内容：** 用户直接把手机里拍的照片传上来就行，系统自己压缩，不会因为一张八兆的原图把访客的首屏拖垮。想放视频当头图也可以，系统会先拿首帧当封面，视频加载好了再播。

**阻塞项：** 07 个人页内容编辑

**状态：** ready-for-human

- [x] 头像与背景图上传后转为 AVIF 为主、WebP 兜底，并生成缩略图
- [x] 视频仅校验格式、时长与大小，**不做服务端转码**，运行镜像不依赖 ffmpeg
- [x] 视频超出限制时给出说明具体原因的错误，而非笼统失败
- [x] 上传视频时在浏览器端用 canvas 抽取首帧作为封面一并提交；抽帧失败则降级为要求用户手动上传封面
- [x] 公开页先渲染封面图，视频加载完成后才开始播放，**视频不得成为最大内容绘制元素**
- [x] 视频在页面上自动循环、静音、行内播放

## Comments

**实现记录（2026-08-27）**

**先做了 10 再做 09。** ticket 编号上 09 在前，但 09 的「用户可上传背景图」要用到本 ticket 的上传管线，先做 09 会留下一条半截的路径。依赖顺序实际是 08 → 10 → 09 → 11。

- 图片走 sharp：先按 EXIF 转正（否则竖拍的照片会躺着），再按用途限最长边（头像 640、背景 1440），输出 AVIF + WebP 各一份加一张 160px 缩略图。`<picture>` 里 AVIF 在前，`<img>` 的 src 落在 WebP 那一档。
- **视频只校验不转码**，运行镜像因此不装 ffmpeg。但「时长超限要说清楚超了多少」仍然要求服务端知道时长，所以写了个只解析 `moov/mvhd` 一个盒的 mp4 读头函数（`readMp4Info`，shared 内纯函数，单测覆盖 version 0/1、盒序错位、截断、盒长度撒谎、timescale 为零）。它不解码任何一帧。
- 拒绝视频时按 format / size / duration 分开给原因，消息里带上实际值（「不能超过 15 秒，这段有 21.4 秒」）。「上传失败」帮不到任何人。
- **视频不得成为 LCP 元素**：`<video>` 带 poster、`preload="none"`、不带 autoplay；被 preload 且标 `fetchpriority="high"` 的是封面图。内联的那一小段脚本在 `requestIdleCallback` 里才把 preload 改成 auto 并在 `canplay` 后 play。有测试直接断言这几条。
- 封面必须与视频同一次请求提交，缺封面直接拒绝并在错误文案里指出「浏览器端抽帧失败时请手动上传一张封面图」。浏览器端抽帧在 `packages/admin/src/media/extract-poster.ts`，抽不出来返回 null 由调用方降级——**该模块本 ticket 只写了函数，接进编辑器 UI 在 11**。
