# Link Profile v1

Status: ready-for-agent

术语一律以 [CONTEXT.md](../../CONTEXT.md) 为准。需求依据 [docs/requirements.md](../../docs/requirements.md)，关键决策见 [docs/adr/](../../docs/adr/)，视觉依据 [docs/design/public-page.html](../../docs/design/public-page.html)。

## 问题陈述

我们在 TikTok 和 Instagram 上做引流，但两个平台的简介栏都只允许放一条链接。真正会带来线索的渠道是 WhatsApp 和 Messenger，而它们挤不进那唯一的位置。结果是：访客看完视频想联系，却找不到入口，线索就这么流失了。

更麻烦的是我们完全不知道流失了多少。没有任何数据能回答「哪个平台带来的线索最多」「访客到底点没点联系方式」「几点发帖引流最划算」这类问题，投放全靠猜。

## 解决方案

给每个人一个可自定义的**个人页**，地址是 `域名/{short_name}`，把这一条链接挂进社媒简介，背后收拢全部渠道。

页面只服务一件事：**换来一次联系**。因此**联系类渠道**和**内容类链接**在视觉上被明确分级——前者是实心卡片，后者是描边行，分级由 `is_lead` 标记直接决定。

同时记录每一次**页面浏览**和**点击**，按国家城市、设备类型与操作系统、**来源**拆分，算出**点击率**，并用趋势图和 24 小时分布图回答「什么时候发帖最划算」。

## 用户故事

### 访客

1. 作为访客，我希望在社媒简介点开链接就看到对方的头像、名字和简介，从而立刻确认自己没点错人
2. 作为访客，我希望一眼就能分辨哪些是联系方式、哪些只是内容链接，从而不用逐条读完再决定点哪个
3. 作为访客，我希望点 WhatsApp 图标直接跳进对话窗口，从而不用手动复制号码再切换 App
4. 作为访客，我希望点 email 直接唤起邮件客户端并填好收件人，从而不用记地址
5. 作为访客，我希望点 Messenger 直接开对话而不是跳到对方的 Facebook 主页，从而少走一步
6. 作为访客，我希望在移动网络下首屏一秒内出来，从而不会因为等待而退出
7. 作为访客，我希望头图位的短视频自动循环播放且静音，从而不用点击就能感受到对方是个真人
8. 作为访客，我希望把这个链接转发到 WhatsApp 时对方看到正确的预览卡片，从而愿意点开
9. 作为访客，我希望用平板或桌面打开时排版依然正常，从而不必换设备
10. 作为访客，我希望访问一个不存在的 short_name 时得到明确的 404，从而知道是链接错了
11. 作为访客，我希望访问一个已注销用户的旧链接时得到 404 而不是陌生人的页面，从而不会被误导到无关的人那里

12. 作为用户，我希望用管理员给我的账号和密码登录后台，从而开始配置自己的页面

14. 作为用户，我希望修改显示名和简介，从而让页面像我本人
15. 作为用户，我希望上传头像后系统自动压缩，从而不必自己处理图片就能保证页面够快
16. 作为用户，我希望上传一段短视频当头图，系统自动取首帧当封面，从而首屏不会被视频拖慢
17. 作为用户，我希望在五种布局之间切换，从而挑一个最适合我素材的排版
18. 作为用户，我希望在六套配色之间切换，从而让页面符合我的调性
19. 作为用户，我希望上传自己的背景图并调整遮罩深浅，从而在个性化的同时保证文字还看得清

22. 作为用户，我希望拖拽调整按钮顺序，从而把最重要的放最前面
23. 作为用户，我希望把某个按钮标记为联系类，从而让它在页面上获得更高的视觉权重并计入线索

39. 作为管理员，我希望重置名下用户的密码，从而在他忘密码时立刻解决
40. 作为管理员，我希望代改名下用户的页面内容，从而在运营统一控版时不必逐个通知本人
41. 作为管理员，我希望修改名下用户的 short_name，从而在确有必要时替他改地址
42. 作为管理员，我希望删除名下用户，从而清理离职或停用的账号
43. 作为管理员，我希望查看名下用户的数据分析，从而汇总小组的整体业绩

### 超级管理员

44. 作为超级管理员，我希望创建管理员账号，从而把用户管理的日常工作分派出去
45. 作为超级管理员，我希望删除管理员，从而在他离职时收回权限
46. 作为超级管理员，我希望被删除的管理员名下的用户转为无归属且在后台显眼可见，从而不会有账号悄悄变成没人管
47. 作为超级管理员，我希望把无归属的用户重新指派给某个管理员，从而恢复正常管理
48. 作为超级管理员，我希望看到全部用户不受归属限制，从而掌握全局
49. 作为超级管理员，我希望设置来源参数透传的全局默认值，从而统一口径而不必逐个用户配置

### 运维

50. 作为运维，我希望用环境变量在首次启动时自动建出超级管理员，从而不必手工进库插数据
51. 作为运维，我希望重复启动时不会重复创建超级管理员，从而可以放心重启
52. 作为运维，我希望一条 `docker compose up` 起完应用和数据库，从而部署流程不依赖宿主机预装
53. 作为运维，我希望应用只监听 HTTP，从而 TLS 和反向代理由我按现有方案接管

### 数据正确性

54. 作为用户，我希望社媒爬虫抓取页面生成分享卡片时不被计入我的浏览数，从而点击率不会因为分享得多反而变难看
55. 作为运维，我希望访客 IP 在解析出地域后立刻被截断存储，从而规避 GDPR / CCPA 下的个人数据风险
56. 作为运维，我希望超过六个月的埋点明细自动聚合进日汇总后删除，从而数据库不会无限膨胀且历史图表不断档

## 实现决策

### 包结构

四个包，依赖方向单一：

- **shared** —— drizzle schema、共享类型、以及一组无 I/O 的归一化纯函数（截断 IP、清洗 `src`、UA 解析为设备类型与操作系统、批量导入行解析）。被其余三个包依赖。
- **profile-ui** —— 个人页的 React 组件，五种布局 × 六套主题，tailwind 4 样式。被 server 与 admin 同时依赖。
- **server** —— Fastify 5。承载公开页 SSR、`/_api` 全部接口、静态资源、埋点写入与聚合任务。
- **admin** —— Vite 8 + React 19 + Ant Design 6 的 SPA。

`server` 与 `admin` 都依赖 `profile-ui`：前者用于 `renderToString` 直出，后者挂进 iframe 做实时预览。这是 ADR-0004 的落点，两处共用同一批组件是零漂移的唯一保证。

### 路由命名空间

个人页占据根路径 `域名/{short_name}`。所有系统路径统一带 `_` 前缀（后台、接口、静态资源），因此 short_name 的唯一约束只有一条：不得以下划线开头。见 ADR-0003。

### 数据模型要点

- **用户**持有四个互不兼任的标识字段：账号（登录，唯一）、用户名称（后台中文备注，可重复）、short_name（个人页地址，按小写唯一）、显示名（页面展示，可重复）。
- **归属管理员**是用户表上一个可空外键。为空即「无归属」，仅超级管理员可见。管理员的一切查询都必须带上归属过滤，漏一处就是越权。见 ADR-0005。
- **short_name 墓碑表**：用户删除后 short_name 迁入墓碑并永不释放，命中墓碑返回 404。
- **按钮**归属于用户，含标题、选填副标题、目标链接、排序位、`is_lead` 标记、来源透传开关。**不分组**——全部按钮共处一个有序列表，联系类与内容类可以混排，页面上没有区段标题。
- **社媒图标**是一组可逐个启用的条目，取值限定于内置的海外平台清单，绝不含大陆 app。用户填的是号码或邮箱，目标 URL 由系统拼装。
- **埋点**分页面浏览与点击两张明细表，外加一张日汇总表。明细保留六个月，超期聚合后删除，日汇总永久保留。
- **会话**存库，30 天过期。删账号或改密码时删除对应会话，立即踢下线。

### 主题令牌

### 公开页渲染

服务端 `renderToString` 直出纯 HTML，**不做 hydration**——浏览器不下载也不解析 React runtime，客户端只保留一小段原生 JS 负责点击埋点并把来源参数带上。这是移动端 LCP 的硬约束，不是风格偏好。见 ADR-0004。

关键 CSS 内联进文档头，头像与背景图 `preload` 且标记高优先级。视频不得成为 LCP 元素：封面图先渲染，视频加载完成后才播放。

输出 `noindex` 阻止搜索引擎收录，但保留完整 og 标签供社媒爬虫抓取分享卡片——两者并行不冲突。

### 实时预览

后台编辑页把 profile-ui 组件挂进 iframe，用 `postMessage` 灌入未保存的草稿状态。iframe 同时解决两件事：真实的 375px 移动端视口，以及 tailwind preflight 与 Ant Design reset 的样式隔离。尚未上传的媒体以 blob URL 传入。

### 埋点写入路径

每次公开页渲染写一条页面浏览，每次点击写一条点击。写入前依次：按 User-Agent 识别爬虫，**识别为爬虫则直接不写记录**（页面照常返回，分享卡片不受影响）；用完整 IP 查出国家与城市后立即截断 IP 再落库；解析 UA 得到设备类型与操作系统；校验并清洗地址上的 `src` 参数，超出字符集或长度即丢弃。

**不做任何访客去重，全部纯计次**。见 ADR-0006。

### 来源追踪

个人页地址可带 `src` 参数投放。按钮的目标 URL 可逐条开启来源透传，超级管理员可设全局默认。已知取舍：统一使用 `src` 而非 `utm_source`，因此第三方网站的分析工具无法直接归因，透传仅在目标为自家页面时有效。

### 时区

底层一律存 UTC。后台提供展示时区下拉，默认受众所在时区。趋势图切天与 24 小时分布图分桶都按所选展示时区计算，不是按服务器时区。

### 媒体处理

图片上传后转 AVIF 为主、WebP 兜底，并生成缩略图。视频只校验格式、时长与大小，**不做服务端转码**，因此运行镜像不需要装 ffmpeg。封面图在浏览器端用 canvas 从首帧抽取后随视频一并上传；抽帧失败则降级为要求用户手动上传封面。

## 测试决策

### 什么是好测试

只测**外部可观察的行为**，不测实现细节。断言的对象是「给定这个请求，响应和落库结果应该是什么」，不是「某个内部函数被调用了几次」。测试不感知模块内部如何分层，因此重构内部结构不应该让任何测试变红。

### 接缝

本仓库为全新建，**没有可复用的既有接缝**。新提两道，不再更多：

**主接缝 —— HTTP，经 Fastify 的进程内请求注入。** 不开端口、不走网络，但完整穿过所有插件、hook、鉴权与序列化。覆盖：公开页 SSR 输出、埋点写入与读回、认证与三级 RBAC、归属过滤、批量创建、后台增删改查、数据分析查询、媒体上传。这是能取到的最高接缝，绝大多数用户故事都在这里验证。

**副接缝 —— shared 包内的归一化纯函数。** 只给无 I/O 且输入空间组合爆炸的那几个：截断 IP、清洗 `src`、UA 解析为设备类型与操作系统、批量导入行解析。它们是纯函数而非实现细节，直接测不脆；走 HTTP 逐个构造边界用例则既慢又绕。

### 测试数据库

用 docker-compose 起一个独立的测试库，每个测试文件使用独立 schema，跑完 drop。本地与 CI 同一套，无额外依赖。**不 mock ORM**——那会把接缝拉到很低的位置，且测不出 SQL 层面的真错。

### 重点覆盖

- 三级角色的每一项权限边界，尤其管理员的归属过滤：管理员访问非名下用户的任何接口都必须被拒
- 归属管理员被删除后，其名下用户转为无归属且仅超级管理员可见
- short_name 墓碑：删除后原地址返回 404，且新用户无法抢注
- 批量导入的部分失败：成功行照常创建，失败行带行号与原因返回
- 爬虫 User-Agent 不产生任何埋点记录，但页面与 og 标签照常返回
- IP 截断后仍能查出正确的国家与城市
- 时区切换后趋势图切天与 24 小时分桶的归属正确，尤其跨日边界
- 五种布局在缺少头图素材时以主题渐变填充，不回落到其他布局

### 既有同类测试

无。本规格实现的是仓库中第一批测试，其结构将成为后续的参照。

## 范围外

站内聊天 · 底部常驻联系条 · 按钮分组与区段标题 · 按钮独立追踪短链 · 长 URL 压缩 · 用户自由调色 · 邮件服务 · Redis · 视频服务端转码 · 公开注册 · 计费 · 访客去重与真实人数统计 · TLS 与反向代理配置 · 浏览器端端到端测试

## 补充说明

- 视觉依据是 `docs/design/public-page.html`，含五种布局的 375px 稿、六套主题的完整令牌、字号阶梯与间距规格。该稿已经客户确认。
- 稿中人像为 GAN 生成的虚构人物，仅作占位，不进产物。
- 社媒品牌图形取自 Simple Icons（CC0），保留各平台注册品牌色，商标归各自权利人所有。品牌按钮样式可参考 LittleLink（MIT），导入时须剔除大陆平台。
- Facebook 与 Messenger 的品牌色同为 `#0866FF`，是 Meta 统一蓝色后的现状，不是笔误，两者靠图形区分。
- 设计基准宽度 375px 指的是**必须不出问题的最小宽度**，桌面端向上适配。
