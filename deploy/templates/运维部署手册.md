# 运维部署手册

这份文档面向第一次接手的人，照着从上往下做就行，不需要读代码，也不需要懂 Node。

**这个仓库里没有源码，只有编译好的产物。**开发那边每次发版会往这里推一个提交，你在服务器上
拉下来、build 成镜像、重启容器，就完成一次部署。

有两件事请先记住，后面会反复提到：

1. **不能新旧两个应用容器同时开着。** 数据库迁移是在应用启动时自动执行的，没有加锁，两个实例
   同时启动会一起改表结构，后果不可预测。所以升级顺序永远是**先停旧、再起新**。
2. **没有自动备份，数据库迁移也没有回退脚本。** 一旦某次发版带了新的迁移，上线之后就回不到旧
   版本了。第 4 步会教你怎么在上线前判断这一点。

## 第 1 步：确认服务器上有什么

```bash
docker --version           # 要 24 以上
docker compose version     # 要 v2，注意是 "docker compose" 不是 "docker-compose"
git --version
nginx -v                   # 要 1.25.1 以上
```

有一条报「command not found」就先装上再往下走。

**服务器要能上外网的这两个地方**（build 镜像时要用）：

| 地址 | 用来做什么 |
| --- | --- |
| `registry-1.docker.io`、`auth.docker.io`、`production.cloudflare.docker.com` | 拉 `node:22-bookworm-slim` 和 `postgres:18-alpine` 基础镜像 |
| `registry.npmjs.org` | 装应用的依赖 |

内网有 npm 镜像源和 Docker 镜像源的话也可以，配好了同样能 build。

**运行时还有一条**：如果后台开启了「自助注册」，应用容器必须能访问 `www.google.com:443` ——
注册页的人机验证（reCAPTCHA）要调 Google 的接口校验。这条不通的表现很隐蔽：健康检查照常是 `ok`，
只是所有人注册都失败，报 `recaptcha_failed`。不开自助注册就不需要。

**硬件**：内存 2 GB 以上，磁盘 15 GB 以上。

## 第 2 步：第一次部署

### 2.1 拉代码

```bash
sudo install -d -o "$USER" -g "$(id -gn)" /srv/link-profile
git clone git@gitlab.195322.xyz:chromeextentions/others/link-profile.git /srv/link-profile
cd /srv/link-profile
```

拉不下来就是这台服务器的 SSH key 没加到 GitLab。把 `~/.ssh/id_ed25519.pub`（没有就
`ssh-keygen -t ed25519` 生成一个）交给 GitLab 管理员，加成这个项目的 Deploy Key。

### 2.2 填配置

```bash
cp .env.example .env
chmod 600 .env
vi .env
```

必须填的五项：

| 变量 | 怎么填 |
| --- | --- |
| `APP_IMAGE` | 保持 `link-profile:local` 不用改。这是下一步 build 出来的镜像名 |
| `POSTGRES_PASSWORD` | 用 `openssl rand -hex 32` 生成。**只能是字母和数字**，因为它会被直接拼进数据库连接串，出现 `/ ? # @` 会把连接串拼坏 |
| `SUPERADMIN_ACCOUNT` | 超级管理员的登录名，保持 `admin` 也行 |
| `SUPERADMIN_PASSWORD` | 超管初始密码。**只在数据库为空时生效**，第一次登录后请在后台改掉 |
| `PUBLIC_ORIGIN` | 网站对外的完整地址，例如 `https://links.example.com`。带 `https://`，**末尾不要斜杠** |

`TRUST_PROXY` 保持默认的 `172.28.0.1` 就行。它是容器网络的网关地址，应用靠它识别访客真实 IP。
填错不会报错，只会让所有访客 IP 都记成这个内网地址。

**`docker-compose.yml` 本身永远不要改。**它归 git 管，升级时会被整个还原（第 4 步会讲）。
需要按现场调整的东西 —— 最常见的是网段 `172.28.0.0/24` 与服务器已有网络冲突 —— 全部写进
`docker-compose.override.yml`，这个文件不归 git 管，升级不会动它，compose 启动时会自动合并进来。

先看有没有冲突：

```bash
ip route | grep -E '172\.28\.'      # 有输出说明冲突，得换个网段
```

有冲突就新建 `docker-compose.override.yml`（网段与网关自己挑一个空闲的，两处一起改）：

```yaml
networks:
  default:
    ipam:
      config:
        - subnet: 172.29.0.0/24
          gateway: 172.29.0.1
```

**然后把 `.env` 里的 `TRUST_PROXY` 改成同一个网关**（上例是 `172.29.0.1`）。这两处必须一致，
不一致不会报错，只会把访客 IP 全记成网关。

```bash
mkdir -p geoip      # 地域库目录，暂时留空也行，国家和城市会显示未知
```

### 2.3 部署

仓库里自带一个部署脚本，构建、启动、等健康检查、记录版本全在里面，任何一步失败都会停下：

```bash
./deploy.sh
```

它依次做：`docker build`（第一次要几分钟，要拉基础镜像、装依赖）→ 启动两个容器 → **等到应用真的
健康**（最多 3 分钟）→ 请求 `/_api/health` 确认返回 `ok` → 把这一版记进 `.deployed-commit`。
应用启动时会**自动执行数据库迁移**、**自动创建超级管理员**，不需要手动跑任何 SQL。

最后一行看到 `✓ 已部署 ...` 就成功了。看到 `✗` 就是某步失败，脚本会打出最近 40 行应用日志，
按「常见问题」查。

### 2.4 确认起来了

```bash
docker compose ps
```

两个服务都应当是 `healthy`。

```bash
curl --fail http://127.0.0.1:3000/_api/health
```

要看到 `{"status":"ok","database":"ok"}`。`--fail` 别省：不加它，接口返回 503 命令也不报错。

看到 `database":"unreachable"` 就是数据库没连上，先看日志：

```bash
docker compose logs app | tail -30
docker compose logs postgres | tail -30
```

### 2.5 配 Nginx

应用只监听 `127.0.0.1:3000`，外网进不来，必须由 Nginx 转发并提供 HTTPS。下面这份配置直接可用，
把 `links.example.com` 和证书路径换成你自己的。

`/etc/nginx/snippets/link-profile-proxy.conf`（转发规则，两个 location 共用）：

```nginx
proxy_pass http://127.0.0.1:3000;
proxy_http_version 1.1;

proxy_set_header Host              $host;
proxy_set_header X-Real-IP         $remote_addr;
proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_set_header X-Forwarded-Host  $host;

# 视频头像靠 206 分段请求拖动，缓冲会破坏它
proxy_buffering off;
```

`/etc/nginx/conf.d/link-profile.conf`（站点）：

```nginx
# 登录接口限速。应用自己没有限速，这层是目前唯一的兜底
limit_req_zone $binary_remote_addr zone=lp_login:10m rate=6r/m;

server {
    listen 80;
    server_name links.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name links.example.com;

    ssl_certificate     /etc/ssl/certs/links.example.com.pem;
    ssl_certificate_key /etc/ssl/private/links.example.com.key;

    # 视频头像是「视频 + 封面」两个文件一次上传，上限分别 10 MB 与 12 MB，
    # 再算上 multipart 编码开销。不写这行默认 1m，任何上传都直接 413
    client_max_body_size 24m;

    location = /_api/auth/login {
        limit_req zone=lp_login burst=3 nodelay;
        limit_req_status 429;
        include /etc/nginx/snippets/link-profile-proxy.conf;
    }

    location / {
        include /etc/nginx/snippets/link-profile-proxy.conf;
    }
}
```

```bash
nginx -t && systemctl reload nginx
```

三点不能省：

- 三个 `X-Forwarded-*` 头一个都不能少，少了访客 IP 会记错
- `client_max_body_size 24m` 不能少也不能小：写 16m 图片能传，但视频头像加封面会 413
- `http2 on;` 要 Nginx 1.25.1 以上。旧版本把 `listen 443 ssl;` 和 `http2 on;` 两行合成 `listen 443 ssl http2;`

`APP_PORT` 改过的话，snippet 里 `proxy_pass` 的端口跟着改。

### 2.6 最后检查一遍

- [ ] 浏览器打开 `https://你的域名/_admin/`，能看到登录页
- [ ] 用 `.env` 里的超管账号密码登进去。**必须走 https 的域名**，直接开
      `http://127.0.0.1:3000` 登录会提示成功但下一页又回到登录页 —— 登录态的 cookie 只在 https 下生效，不是故障
- [ ] **进去后马上改超管密码**
- [ ] `ss -lntp | grep :3000` 只显示 `127.0.0.1`，没有 `0.0.0.0`
- [ ] **如果要开自助注册**：在后台「全站设置」里填好 reCAPTCHA 两把密钥并打开开关后，用「区域」页
      的邀请码走一遍注册页，能注册成功。失败提示 `recaptcha_failed` 就是容器出不了网到
      `www.google.com`，见第 1 步的运行时出网要求
- [ ] **访客 IP 记对了**：用手机流量（别用公司 wifi）打开一次任意个人页，然后查：

      ```bash
      docker compose exec -T postgres psql -U linkprofile -d link_profile \
        -tAc 'select ip_truncated, country from page_views order by occurred_at desc limit 5'
      ```

      **IP 入库前会把最后一段抹成 0**（脱敏），所以看到的不是完整地址：手机公网 IP 是
      `203.0.113.42` 的话，表里存的是 `203.0.113.0`。这是正常的，只看前三段是不是你手机的公网网段。
      看到 `172.28.0.0`（网关抹零后的样子）或 `192.168.x.0`，就是 `TRUST_PROXY` 或 Nginx 的
      `X-Forwarded-For` 配错了，回 2.2 和 2.5 对一遍

## 第 3 步：怎么知道现在跑的是哪一版

```bash
cd /srv/link-profile
cat .deployed-commit          # 服务器上实际在跑的提交，deploy.sh 每次成功后自动写
cat deploy-manifest.json      # 这一版的版本号、源仓库提交、打包时间
```

出问题找开发时，把这两个文件的内容一起发过去，他们凭 `commit` 能精确定位到是哪份代码。

`.deployed-commit` **只在部署脚本跑到最后健康检查通过时才会更新**，构建失败、容器起不来、健康检查
不过都不会写。所以它记的永远是真正跑起来过的那一版 —— 第 4 步判断「这次升级能不能回退」全靠它。
别手动改它。

## 第 4 步：有新提交了，怎么升级

开发推了新版本会通知你。一条命令：

```bash
cd /srv/link-profile
./deploy.sh
```

脚本会先告诉你这次改了什么，然后做一个关键判断：**这次带没带数据库迁移**。

- 没带：直接往下走。这种升级随时可以回退。
- 带了：脚本会列出迁移文件并**停下来问你**。带迁移的版本上线后**无法回退** —— 迁移会改数据库
  表结构，没有回退脚本也没有备份。这时先跟开发和业务方确认一句再按 `y`，别自己扛。

确认之后脚本会：拉最新 → 构建（**失败的话旧容器还在跑，网站不受影响**）→ 停旧容器 → 起新容器
（这两步之间网站中断，实测约 20 秒）→ 等健康 → 记录版本。

**为什么不自己敲命令**：整块复制执行时，前面一步失败后面的不会停，最后仍会把没跑起来的版本记成
「实际在跑」，下次升级的迁移判断就错了。脚本每一步失败即停，`.deployed-commit` 只在最后写。

脚本比较的基准是 `.deployed-commit`（服务器上实际在跑的版本），不是本地检出的提交。所以回滚过、
或上次失败重来过，判断都还是对的。

**千万不要**为了图快自己跑 `docker compose down -v`。`-v` 会连数据库卷一起删掉，在没有备份的前提下
所有数据都没了，找不回来。脚本里的 `down` 不带 `-v`。

### 升级后看什么

- 脚本最后一行是 `✓ 已部署 ...`
- `docker compose ps` 两个都 `healthy`
- 浏览器打开后台能正常登录
- `docker compose logs app | grep bootstrap` 应当是 `already-exists`，说明没有重复创建超管

### 脚本报 ✗ 了怎么办

| 停在哪 | 线上状态 | 怎么办 |
| --- | --- | --- |
| 构建镜像 | **旧版还在跑，没受影响** | 看输出里的错误，多半是出网问题（见第 1 步）。修好重跑 `./deploy.sh` |
| 等待应用健康 / 健康检查 | **线上是停的** | 脚本已打出应用日志，按「常见问题」查。没带迁移的话可以先 `./deploy.sh <上一个提交>` 回退止血（提交 id 在 `.deployed-commit`，或 `git log --oneline`），再慢慢查 |

## 第 5 步：回滚

**前提：要回退的这几版之间没有新的迁移。**有迁移就回不去，脚本会拒绝并告诉你，这时只能找开发出修复版本。

```bash
cd /srv/link-profile
git log --oneline -5              # 找到要回到的那个 deploy 提交的 id
./deploy.sh <那个提交的 id>
```

脚本认出这是回滚（目标比当前旧），会检查中间有没有迁移，没有才执行。成功后 `.deployed-commit`
会自动更新成回滚到的版本。

回滚之后告诉开发你回到了哪个提交。之后要跟上新版本，直接 `./deploy.sh` 即可。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `docker compose up` 报 `POSTGRES_PASSWORD 必须显式设置` | `.env` 没建或没填。回到 2.2 |
| 数据库容器反复报 `Error: in 18+, these Docker images are configured to store...` | 数据卷是老版本 postgres 留下的布局。这台机器以前跑过旧版就会这样。确认卷里没有要留的数据后 `docker compose down -v` 清掉重来；**卷里有生产数据的话别执行**，先找开发 |
| `docker compose up` 报 `APP_IMAGE 必须显式设置` | `.env` 里 `APP_IMAGE` 是空的，填 `link-profile:local` |
| 应用容器反复重启 | `docker compose logs app` 看日志。多半是数据库密码里有特殊字符，或 `.env` 某项没填 |
| `/_api/health` 返回 `database":"unreachable"` | 数据库容器没起来或密码不对。`docker compose logs postgres` |
| 打开 `/_admin/` 是 503，提示 `admin_not_built` | 产物不完整，找开发重新推一次 |
| 上传图片或视频头像报 413 | Nginx 的 `client_max_body_size` 没配或小于 24m，见 2.5 |
| 后台里访客 IP 全是 `172.28.0.0` | `.env` 的 `TRUST_PROXY` 与网关不一致，或 Nginx 没转发 `X-Forwarded-For`。（存的是抹零后的网关，所以尾段是 0） |
| 所有人注册都报 `recaptcha_failed`，健康检查却正常 | 应用容器访问不到 `www.google.com:443`。见第 1 步运行时出网 |
| 国家和城市都显示未知 | 还没放 GeoIP 库，或**文件名不对**。应用不扫目录，只打开 `.env` 里 `GEOLITE2_CITY_PATH` 指定的那一个文件，默认是 `geoip/GeoIP-City.mmdb`。MaxMind 下载下来叫 `GeoLite2-City.mmdb`，要么改名成 `GeoIP-City.mmdb` 放进 `geoip/`，然后 `docker compose restart app`；要么改 `.env` 的 `GEOLITE2_CITY_PATH` 指向实际文件名，**改了 `.env` 必须 `docker compose up -d` 重建容器**，`restart` 不会读新的环境变量。文件名不匹配不会报错，只会一直「未知」 |
| build 卡在装依赖 | 服务器上不了 npm registry。见第 1 步的出网要求 |
| 磁盘满了 | `docker system prune -a` 清构建缓存。**不要加 `--volumes`**，那会删数据库 |

## 日常维护

```bash
docker compose ps                      # 看状态
docker compose logs -f app             # 实时看日志，Ctrl+C 退出
docker compose restart app             # 只重启应用，不动数据库（改了 .env 不能用它，要 ./deploy.sh 或 docker compose up -d）
docker stats --no-stream               # 看资源占用
df -h /                                # 看磁盘
```

日志由 Docker 自动轮转，单个服务最多占 50 MB，不用手动清。

用户上传的图片和视频存在 Docker 卷 `uploads` 里，**不在这个仓库里**。换服务器时要单独迁移这个卷，
不然所有头像和封面都会丢。

## 找谁

- 部署报错、build 失败、容器起不来：先看上面的常见问题表，解决不了带上 `docker compose logs app`
  的输出找开发
- 要回退但带了迁移：直接找开发，不要自己想办法
- 需要重置超管密码：找开发，有一段专门的应急流程
