# 运维部署手册

这份文档面向第一次接手的人，照着从上往下做就行，不需要读代码，也不需要懂 Node。

**这个仓库里没有源码，只有编译好的产物。**开发那边每次发版会往这里推一个提交，你在服务器上
拉下来、build 成镜像、重启容器，就完成一次部署。

有两件事请先记住，后面会反复提到：

1. **不能新旧两个应用容器同时开着。** 数据库迁移是在应用启动时自动执行的，没有加锁，两个实例
   同时启动会一起改表结构，后果不可预测。所以升级顺序永远是**先停旧、再起新**。
2. **没有自动备份，数据库迁移也没有回退脚本。** 一旦某次发版带了新的迁移，上线之后就回不到旧
   版本了。第 4 步会教你怎么在上线前判断这一点。

## 术语对照

| 说法 | 指的是 |
| --- | --- |
| 产物仓库 | 你现在看的这个 GitLab 仓库 |
| 部署目录 | 服务器上放这个仓库的地方，本文用 `/srv/link-profile` |
| 应用容器 | 跑网站的容器，compose 里叫 `app` |
| 数据库容器 | 跑 PostgreSQL 的容器，compose 里叫 `postgres` |
| 迁移 | `drizzle/` 目录里那些 `.sql` 文件，改数据库表结构用的 |

## 第 1 步：确认服务器上有什么

```bash
docker --version           # 要 24 以上
docker compose version     # 要 v2，注意是 "docker compose" 不是 "docker-compose"
git --version
nginx -v                   # 要 1.25.1 以上
```

有一条报「command not found」就先装上再往下走。

**服务器要能上外网的这两个地方**（build 镜像时要用）：

| 地址 | 用来做什么 |
| --- | --- |
| `registry-1.docker.io`、`auth.docker.io`、`production.cloudflare.docker.com` | 拉 `node:22-bookworm-slim` 和 `postgres:18-alpine` 基础镜像 |
| `registry.npmjs.org` | 装应用的依赖 |

内网有 npm 镜像源和 Docker 镜像源的话也可以，配好了同样能 build。

**硬件**：内存 2 GB 以上，磁盘 15 GB 以上。

## 第 2 步：第一次部署

### 2.1 拉代码

```bash
sudo install -d -o "$USER" -g "$(id -gn)" /srv/link-profile
git clone git@gitlab.195322.xyz:chromeextentions/others/link-profile.git /srv/link-profile
cd /srv/link-profile
```

拉不下来就是这台服务器的 SSH key 没加到 GitLab。把 `~/.ssh/id_ed25519.pub`（没有就
`ssh-keygen -t ed25519` 生成一个）交给 GitLab 管理员，加成这个项目的 Deploy Key。

### 2.2 填配置

```bash
cp .env.example .env
chmod 600 .env
vi .env
```

必须填的五项：

| 变量 | 怎么填 |
| --- | --- |
| `APP_IMAGE` | 保持 `link-profile:local` 不用改。这是下一步 build 出来的镜像名 |
| `POSTGRES_PASSWORD` | 用 `openssl rand -hex 32` 生成。**只能是字母和数字**，因为它会被直接拼进数据库连接串，出现 `/ ? # @` 会把连接串拼坏 |
| `SUPERADMIN_ACCOUNT` | 超级管理员的登录名，保持 `admin` 也行 |
| `SUPERADMIN_PASSWORD` | 超管初始密码。**只在数据库为空时生效**，第一次登录后请在后台改掉 |
| `PUBLIC_ORIGIN` | 网站对外的完整地址，例如 `https://links.example.com`。带 `https://`，**末尾不要斜杠** |

`TRUST_PROXY` 保持默认的 `172.28.0.1` 就行。它是容器网络的网关地址，应用靠它识别访客真实 IP。
填错不会报错，只会让所有访客 IP 都记成这个内网地址，所以别动它，除非你改了 `docker-compose.yml`
里的网段 —— 那两个值必须一致。

```bash
mkdir -p geoip      # 地域库目录，暂时留空也行，国家和城市会显示未知
```

### 2.3 Build 镜像

```bash
docker build -t link-profile:local .
```

第一次要几分钟（要拉基础镜像、装依赖），之后有缓存会快很多。

看到最后一行是 `naming to docker.io/library/link-profile:local` 就成功了。

### 2.4 启动

```bash
docker compose up -d
```

应用启动时会**自动执行数据库迁移**、**自动创建超级管理员**，不需要你手动跑任何 SQL。

### 2.5 确认起来了

```bash
docker compose ps
```

两个服务都应当是 `healthy`。数据库容器要十几秒才变健康，应用会等它。

```bash
curl http://127.0.0.1:3000/_api/health
```

要看到 `{"status":"ok","database":"ok"}`。

看到 `database":"unreachable"` 就是数据库没连上，先看日志：

```bash
docker compose logs app | tail -30
docker compose logs postgres | tail -30
```

### 2.6 配 Nginx

应用只监听 `127.0.0.1:3000`，外网进不来，必须由 Nginx 转发并提供 HTTPS。
完整的 Nginx 配置在开发那边的 `docs/deployment.md` 第 5 节，找开发要一份。要点：

- `client_max_body_size 16m`，否则用户上传大图会得到 413
- 转发时带上 `X-Forwarded-For`、`X-Forwarded-Proto`、`X-Forwarded-Host`
- `proxy_buffering off`，视频头像要用到断点续传

配完 `nginx -t` 通过再 `systemctl reload nginx`。

### 2.7 最后检查一遍

- [ ] 浏览器打开 `https://你的域名/_admin/`，能看到登录页
- [ ] 用 `.env` 里的超管账号密码登进去
- [ ] **进去后马上改超管密码**
- [ ] `ss -lntp | grep :3000` 只显示 `127.0.0.1`，没有 `0.0.0.0`

cd /srv/link-profile

## 第 4 步：有新提交了，怎么升级

开发推了新版本会通知你。整个过程五条命令，但**第 2 条决定这次升级能不能回退**，别跳过。

```bash
cd /srv/link-profile

# ① 看看这次都改了什么
git fetch
git log --oneline HEAD..origin/master

# ② 关键一步：这次带没带数据库迁移
git diff --stat HEAD..origin/master -- drizzle/
```

**第 ② 条命令有输出，就意味着这次升级不可回退。**因为迁移会改数据库表结构，没有回退脚本也没有
备份。这种情况下先跟开发和业务方确认一句再继续，别自己扛。

没有输出说明这次只改了代码，随时可以回退到上一版。

```bash
# ③ 拉下来并先 build。build 失败的话旧容器还在跑，网站不受影响
git pull
docker build -t link-profile:local .

# ④ build 成功后再切换。这两条命令之间网站会中断，实测约 20 秒
docker compose down
docker compose up -d

# ⑤ 确认
docker compose ps
curl http://127.0.0.1:3000/_api/health
docker compose logs app | tail -20
```

**第 ④ 步的 `down` 后面千万不要加 `-v`。**加了会连数据库卷一起删掉，在没有备份的前提下所有数据
都没了，找不回来。

顺序也别改成先 `up` 再 `down`，那样会有一瞬间两个应用容器同时在跑，正好撞上开头说的迁移无锁问题。

### 升级后看什么

- `curl http://127.0.0.1:3000/_api/health` 返回 `ok`
- 日志里有 `Server listening`，没有大段红色报错
- 浏览器打开后台能正常登录
- 日志里 `bootstrap` 应当是 `already-exists`，说明没有重复创建超管

## 第 5 步：回滚

**前提：这两版之间没有新的迁移。**有迁移就回不去，只能找开发出修复版本。

```bash
cd /srv/link-profile
git log --oneline -5                    # 找到上一个 deploy 提交的 id
git checkout <上一个提交的 id>
docker build -t link-profile:local .
docker compose down
docker compose up -d
curl http://127.0.0.1:3000/_api/health
```

回滚之后记得告诉开发你回到了哪个提交。

后续要跟上新版本，用 `git checkout master && git pull` 回到最新。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `docker compose up` 报 `POSTGRES_PASSWORD 必须显式设置` | `.env` 没建或没填。回到 2.2 |
| `docker compose up` 报 `APP_IMAGE 必须显式设置` | `.env` 里 `APP_IMAGE` 是空的，填 `link-profile:local` |
| 应用容器反复重启 | `docker compose logs app` 看日志。多半是数据库密码里有特殊字符，或 `.env` 某项没填 |
| `/_api/health` 返回 `database":"unreachable"` | 数据库容器没起来或密码不对。`docker compose logs postgres` |
| 打开 `/_admin/` 是 503，提示 `admin_not_built` | 产物不完整，找开发重新推一次 |
| 上传图片报 413 | Nginx 的 `client_max_body_size` 没配，见 2.6 |
| 后台里访客 IP 全是 `172.28.0.1` | `.env` 的 `TRUST_PROXY` 与 compose 网段不一致，或 Nginx 没转发 `X-Forwarded-For` |
| 国家和城市都显示未知 | 正常，还没放 GeoIP 库。要用就把 MMDB 文件放进 `geoip/` 目录再重启应用容器 |
| build 卡在装依赖 | 服务器上不了 npm registry。见第 1 步的出网要求 |
| 磁盘满了 | `docker system prune -a` 清构建缓存。**不要加 `--volumes`**，那会删数据库 |

## 日常维护

```bash
docker compose ps                      # 看状态
docker compose logs -f app             # 实时看日志，Ctrl+C 退出
docker compose restart app             # 只重启应用，不动数据库
docker stats --no-stream               # 看资源占用
df -h /                                # 看磁盘
```

日志由 Docker 自动轮转，单个服务最多占 50 MB，不用手动清。

用户上传的图片和视频存在 Docker 卷 `uploads` 里，**不在这个仓库里**。换服务器时要单独迁移这个卷，
不然所有头像和封面都会丢。

## 找谁

- 部署报错、build 失败、容器起不来：先看上面的常见问题表，解决不了带上 `docker compose logs app`
  的输出找开发
- 要回退但带了迁移：直接找开发，不要自己想办法
- 需要重置超管密码：找开发，有一段专门的应急流程
